# 知识库 (`world.ts`, `server/`)

她主动查的记忆索引：过去的聊天原文，加上不在前缀里的记忆文件。常聊的事由做梦总结进记忆文件、整篇放在前缀里；知识库只管两种情况——记忆里没有（miss），或者要具体细节（原话、哪天、谁说的）。它不进前缀，也不自动附带，只在她调用工具时检索。设计见 `docs/memory.md` 第 4 节。

## 索引什么

- **聊天原文**（事件库里的 `qq.message`、`qq.self`、控制台消息）：按聊天切段，间隔超过「切段间隔」（30 分钟）或满「每段最多消息数」（20 条）就切。
  - 私聊全收。
  - 群聊默认只收她说过话或被 @ 的段；短于「群聊最短消息」（4 字）的、指令、只有图的消息当噪音丢掉（她自己的和 @ 她的除外），连着复读只留一条；保留「群聊片段保留天数」（30 天）后从索引删掉，事件库里的原文不动。
  - 图片、表情一律只留 `[图]`，不存图也不存识图描述。
- **记忆文件**：`note/`、`memo/archived/`、`groups/`、`kb/`、图像资料的 `entry.md`，按标题切节，太长的再按段落切到 800 字以内。`people/`、宪法、WORLDVIEW、常驻和进行中的 memo 已在前缀里，不索引。

索引是派生数据，在 `<部署>/data/kb/kb.sqlite`，不进记忆的 git，「重建索引」可从头再来。启动时、每「定时索引间隔」（5 分钟）、以及有新对话一分钟后各补一次增量；每个聊天的最后一段还没结束时下次连同新消息一起重切，超过切段间隔就算结束。索引器不调用对话模型。

## 检索

全文检索用 SQLite FTS5 的 trigram 分词：查询里三字以上的词拆成相邻三字片段用 OR 连起来（「生日三月五号」能命中「生日是三月五号」）；两个字的词（黑话、昵称）改用子串匹配。配了「嵌入模型」时再做向量检索（模型中心的嵌入模型，如 `local-bge-m3/bge-m3:latest`），只靠向量命中的结果要达到「向量最低相似度」（0.45），免得毫不相干的记录也被当成"最近"返回。两路各取前 50 用 RRF 合并，乘类型权重（笔记 1、私聊 0.9、群聊 0.7）和很轻的时间衰减，内容高度相似的只留一条，默认返回 5 条。没配嵌入模型时只用全文检索。

## 谁能搜到什么

由这一轮投递进来的对话决定，不信模型传的参数：

- **群里**：只有这个群的聊天和 `groups/<群号>.md`。
- **白名单 QQ 的私聊**（设置 → 全局变量）和控制台：全部。
- **别人的私聊**：和他的私聊，以及有他参与的群聊片段；她的笔记和别人的私聊都搜不到。
- 一轮里同时有群和私聊时按群算。图像资料的条目按 `entry.md` 的来源：私聊所得的只在那个人的私聊里可见。

需要补丁 `0011-world-delivery-hints.patch`（拿到每批投递）和 `0023-persona-settings-globals.patch`（白名单 QQ）。

## 工具

- `recall(query, since?, until?, people?, kind?, k?)`：混合检索；`people` 是 QQ 号，`kind` 是 `chat` 或 `note`。查不到时回执明说没找到，让她照实说不记得。
- `recall_open(id, around?)`：聊天片段附上前后几条原文（含被当成噪音的消息），笔记读全文。
- `group_members(group?, days?)`：直接数事件库，列出某个群最近谁说过话、在群里用过的昵称、条数、最后一次的时间，以及有没有 `people/<QQ号>.md`；不给群号就用当前的群。别人的私聊里不能查群。

人和群都以 QQ 号为准：`people/<QQ号>.md` 是人，`groups/<群号>.md` 是群。

## 管理页

「知识库 → 索引与检索」：片段数、向量数、索引到哪条事件、上次索引的时间和错误；「立即索引」「重建索引」；检索测试框（和 `recall` 同一条路，但不受聊天范围限制）；查群成员。
