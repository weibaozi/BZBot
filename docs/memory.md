# myBot 记忆设计

在 corti-soulmate 现有记忆机制的基础上，补上知识库这一层，组成三层记忆，最底下再加一层原始记录。

相关文档：[整体架构](architecture.md) · [管理后台设计](admin-webui.md)

## 1. 原则

- **按"怎么进入上下文"分层**：每一层先定好它以什么方式进入模型的上下文，这决定了缓存命中和 token 成本。
- **记忆由模型自己管理**：读写、升级、降级都由模型用工具完成。代码只做机械的事（建索引、容量统计、权限检查），并把事实提供给模型（比如"这条被召回过 5 次"），不写死"被召回 N 次就升级"这类规则。
- **原始记录永远不删**：遗忘只表现为检索排序时的权重降低，不做物理删除。
- **派生数据可以重建**：知识库索引全部能从原始记录和工作区文件重新生成。

## 2. 分层

| 层 | 内容 | 存在哪 | 怎么进入上下文 | 谁来写 |
|---|---|---|---|---|
| **0 原始记录** | 所有事件的原文（QQ 消息、工具回执、内部通知） | Cortico 事件库 `data/runs/*` | 不直接进入；作为知识库的数据来源 | Cortico 自动写，只追加 |
| **1 短期记忆** | 当前会话；正在跟进的事；最近几次的交接笔记 | 会话本身、`memo/active/`、`handoffs/` | 当前会话本来就在上下文里；`memo/active/` 在前缀里只列文件名 | 模型 + 交接机制 |
| **2 长期记忆** | 关于你的画像、人格宪法、对环境的综合认知、认识的人、重要约定 | `PARTNER.md`、`CONSTITUTION.md`、`WORLDVIEW.md`、`people/`、`memo/` 常驻区 | **整篇放进前缀**，会话中途冻结 | 平时只能写一部分，其余由做梦写（见第 5 节） |
| **3 记忆知识库** | 情节摘要、原文片段、细节笔记、归档的 memo | `kb/`（工作区里）+ `kb.sqlite` 索引 | 不常驻：`recall` 主动检索，或自动附在当轮事件后面 | 做梦写情节摘要，模型写笔记，索引器自动建索引 |

### 和 corti-soulmate 现有机制的对应

- `memo/` 顶层（常驻）→ 第 2 层；`memo/active/` → 第 1 层；`memo/archived/` → 第 3 层（会被索引）。
- `WORLDVIEW.md`、`people/`、`CONSTITUTION.md` 沿用 soulmate 的读写权限规则。
- **新增**：`PARTNER.md`（参考 Coopanion 的做法：整篇放进前缀，不能用 `delete_file` 删除）、`kb/` 目录、`kb.sqlite`、`recall` 系列工具、第 2 层的整体 token 预算。
- **图像资料** `visual/<id>/`（`entry.md` 加图片，`self` 是她自己）：自设图和别人东西的参考图，由图像资料扩展 `cortico-world-visual` 管理；画图时她自己挑图，把 `mem:visual/<id>/<文件名>` 交给生图扩展；她用 `visual_save` 存白名单里的人发来的图（发送者和聊天从事件库确认）。现在条目列表经环境提示词进前缀，她按 id 选；条目多了再加向量检索（只索引 `entry.md` 的文字，存在记忆目录外，可重建），知识库做好后作为 `kind: visual` 片段并入 `kb.sqlite`，`recall` 返回图片引用。`source: private` 的条目在群里不返回，这条要等检索能按聊天过滤时才有硬兜底。

## 3. 第 2 层：长期记忆

- **整体预算**：新增配置 `memory.longTermBudgetTokens`，默认 2000。超过 90% 时，在下次做梦的任务说明里提示它合并或降级。达到 100% 时，平时写入这一层的工具会拒绝，并说明该怎么处理。
- **保持精简**：`PARTNER.md` 只放提炼过的画像，故事、日志等长内容放到 `partner/` 目录下（这个目录会被索引，属于第 3 层）。
- **前缀冻结**：会话中途修改长期记忆，前缀不会变。模型知道自己改了什么，因为改动记录就在上下文里。新版本要等下次交接或手动重载才进入前缀。后台会显示"已修改，待生效"。
- **人格即时生效（可选）**：借鉴 DeepSeek Harness 的做法，把"人格已更新"作为一条内部消息追加到上下文末尾，让新设定马上生效，但不重建前缀。默认关闭，M3 之后再评估。

## 4. 第 3 层：记忆知识库

### 4.1 数据来源

| 来源 | 切分方式 | 类型标记 |
|---|---|---|
| 事件库里的对话 | 按会话（哪个私聊或群）和时间间隔切成窗口：间隔超过 30 分钟或超过 N 条就切 | `raw` 原文片段 |
| `kb/episodes/*.md` | 一个文件一条；由做梦生成，每段对话一份情节摘要 | `episode` 情节摘要 |
| `kb/notes/`、`partner/`、`memo/archived/` | 按标题或段落切 | `note` 笔记 |

### 4.2 存储（`kb.sqlite`，每个 profile 一个）

```
chunks      id, kind, source_ref, channel, people[], ts_start, ts_end, text, content_hash
chunks_fts  FTS5 全文索引（text）
chunks_vec  sqlite-vec 向量（embedding）
stats       chunk_id, recall_count, last_recalled_at
meta        embedding_model, embedding_dim, indexed_cursor, schema_version
```

- **增量索引**：事件按事件库的游标推进，文件按内容哈希判断是否需要重新索引。索引器是纯机械程序，不调用模型。
- **全量重建**：`meta.embedding_model` 和当前配置不一致，或者手动点"重建索引"时，删表重建。
- **embedding**：调用 OpenAI 兼容的 `/v1/embeddings`。默认用本地 bge-m3，端点地址写在配置里。

### 4.3 检索

1. 全文检索（BM25）取前 30 条，向量检索取前 30 条。
2. 用 RRF（倒数排名融合）合并两组结果，再按时间做轻微衰减。
3. 应用过滤条件：时间范围、人、来源。
4. 返回前 k 条（默认 5 条），每条带上 `id`、类型、时间、来源、各项分数。
5. 每返回一条，就在 `stats` 里给它的召回次数加一。

### 4.4 工具（属于 Persona）

| 工具 | 作用 |
|---|---|
| `recall(query, since?, until?, people?, channel?, kind?, k?)` | 混合检索 |
| `recall_open(id, around?)` | 展开一条结果：原文片段就附上前后几条消息，笔记就读全文 |
| `kb_note(path, text)` | 往 `kb/notes/` 写一条笔记（相当于限定了目录的 `write_file`） |

### 4.5 自动附带

- 配置 `kb.autoRecall`：`off` / `on`。**默认 `on`**，可以在后台关掉。
- 每批外部事件到达时（Persona 的 `onDelivery` 钩子），用这批消息的正文检索一次。只有综合分数高于 `kb.autoRecallThreshold` 的结果才附带，最多 `kb.autoRecallMax` 条（默认 3 条）。
- 附带的内容以内部消息的形式放在这批事件里，比如"[可能相关的记忆] …"。它位于上下文末尾，**不影响缓存**。
- 文字要写成"可能相关"，不能写成"你记得"。这是 Cortico "诚实认知"的要求：基础设施只陈述它能确认的事实。

## 5. 层与层之间的流动

```
           主动写（对话中）              做梦（交接后 / 空闲时）
对话 ──────────────────► 第 1、2、3 层   ◄─────────────── 交接快照
  │                                         │
  └─ 事件库（第 0 层）── 索引器 ──► 第 3 层   ├─ 提炼事实 → 升级到第 2 层
                                            ├─ 写情节摘要 → kb/episodes/
                                            └─ 合并、改写、降级第 2 层
```

### 写入的四条路

1. **对话中主动写**：模型觉得重要时，自己用工具写进对应的层。
2. **交接前提醒**：Cortico 已有的软阈值提醒（"交接快来了，还想记住的现在就写进文件"）。
3. **做梦**（soulmate 已有，需要扩展任务说明）：
   - 给这段对话写一份情节摘要，存到 `kb/episodes/<日期>-<序号>.md`。
   - 提炼值得长期记住的事实，**升级**到第 2 层。
   - 参考召回统计，合并或改写第 2 层里过时的内容，必要时**降级**到 `kb/notes/`，保证第 2 层不超预算。
   - 做梦的任务说明里会附上这些事实：第 2 层当前占用、最近召回次数最多的知识库条目、超过 N 天没被召回的长期记忆条目。
4. **索引器**：发现新事件和新文件就切分、做 embedding、写进索引。

### 读写权限（在 soulmate 的规则上扩展）

| 区域 | 平时 | 做梦时 |
|---|---|---|
| `memo/`、`note/`、`kb/notes/` | 读写 | 读写删 |
| `PARTNER.md`、`partner/` | 读写 | 读写 |
| `people/` | 读 + 追加 | 读写（含合并） |
| `WORLDVIEW.md` | 只读 | 读写 |
| `CONSTITUTION.md` | 只读 | 可修订内容 |
| `kb/episodes/` | 只读 | 读写 |
| `kb.sqlite` | 只能通过 `recall` 访问 | 只能通过 `recall` 访问 |

## 6. 群聊和私聊

- 每条知识库片段都记录 `channel`（私聊或哪个群）和 `people`。
- **默认规则**：私聊里的内容，在群里检索时不返回。配置 `kb.privateInGroups`：`hide`（默认）/ `allow`。
- 在群里时，检索默认只返回这个群和公开笔记里的内容。
- 人格层面的规则（比如"别在群里提他的私事"）写进人格宪法，由模型自己把握；上面的检索过滤只是硬兜底。

## 7. 打包迁移

一个 profile 的完整记忆：

| 内容 | 位置 | 迁移时 |
|---|---|---|
| 工作区（第 1、2 层和 `kb/` 下的文件） | `<部署>/workspace/` | 必须带上；是 git 仓库 |
| 原始记录 | `<部署>/data/` | 必须带上 |
| 知识库索引 | `<部署>/kb.sqlite` | 可以不带，在新机器上重建 |
| 配置 | `<部署>/config.json` | 带上；不包含密钥 |

后台的"导出 bundle"把前两项和配置打成一个压缩包，并在 `manifest.json` 里记下 bot 包版本、embedding 模型和导出时间。导入时检查 bot 包版本，然后重建索引。

## 8. 新增配置项

| 键 | 默认值 | 说明 |
|---|---|---|
| `memory.longTermBudgetTokens` | 2000 | 第 2 层的整体预算 |
| `kb.embedding.baseUrl` / `model` | 本地 bge-m3 | embedding 端点 |
| `kb.autoRecall` | `on` | 每批事件自动检索一次 |
| `kb.autoRecallThreshold` | 待调（M2 用检索测试来定） | 自动附带的分数门槛 |
| `kb.autoRecallMax` | 3 | 每批最多附带几条 |
| `kb.privateInGroups` | `hide` | 群里能否检索到私聊内容 |
| `kb.chunk.gapMinutes` / `maxMessages` | 30 / 待调 | 对话切分规则 |

## 9. 测试要点

- 索引器：增量索引不重复；内容变了会重新索引；换 embedding 模型会触发全量重建。
- 检索：时间、人、来源过滤；私聊内容在群里被隐藏。
- 自动附带：只在超过门槛时附带；附带的内容出现在当批事件里，不在前缀里（看前缀哈希不变）。
- 权限：平时写 `kb/episodes/` 会被拒绝；做梦时可以。
- 预算：第 2 层超出预算时，写入被拒，回执里说明该怎么做。
- 用真实的事件库和真实的 SQLite 测，只有 LLM 和 embedding 用假数据。
