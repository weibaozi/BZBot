# myBot 管理后台设计

界面原型：[myBot 管理后台（设计画布）](https://claude.ai/artifact/JbAcyBCqYVkarTv6NM6mB2)，共 4 页，使用示例数据。

相关文档：[整体架构](architecture.md) · [记忆设计](memory.md)

## 1. 实现方式

- **不另起前端**。所有新页面都作为 Cortico WebUI 的**面板**来实现，登录、主题、路由、多语言都沿用 Cortico 的。面板契约见 Cortico 的 `src/web/shared/client-panel.ts`：浏览器端打包成 `dist/webui.js`，服务端通过面板的 `invoke` 方法提供数据，需要推送的用 WebSocket 流。
- **挂载位置**：
  - 总览、记忆、状态与主动性、备份与迁移 → `cortico-bot-mybot` 的 Persona 页面板（`persona:<bot id>`）。
  - MCP 服务 → `cortico-world-mcp` 的 World 页面板。
  - 委派任务和插件审批 → `cortico-world-delegate` 的 World 页面板。
- **菜单结构由 Cortico 决定**：原型左侧的菜单是理想布局。实际上，这些页会以面板（或页签）的形式出现在 Persona 页和对应的 World 页里。如果之后觉得非要按原型的菜单走，再考虑向 Cortico 提"自定义页面入口"的 issue。第一版不单独写前端。

## 2. 直接用 Cortico 自带的页面

| 原型菜单里的项 | Cortico 页面 |
|---|---|
| 对话 | 控制台 |
| 人格与提示词 | 系统提示词（前缀各段的编辑和预览） |

## 3. 新页面

### 3.1 总览

| 区块 | 内容 | 数据来源 |
|---|---|---|
| 状态头 | 运行中 / 暂停 / 正在处理；当前模型；运行时长 | `GET /api/status` |
| 今日指标 | 收发消息数、主动发起次数（其中被回复的次数）、缓存命中、费用 | 事件库统计 + `GET /api/usage` |
| 上下文与缓存 | 会话 token 和软阈值线、冻结前缀大小、最近一条的命中率、**待生效的修改**和"立即生效"按钮 | `GET /api/status`、工作区与前缀版本对比；按钮调用 `POST /api/session/reload-prefix` |
| 它现在的状态 | 心情、在做什么、想对你说的事、最后更新时间 | `state.json`（见 3.3） |
| 待你处理 | 待审批的插件、运行中的委派任务、长期记忆接近上限 | 各面板汇总 |
| 接下来 | 下次心跳、闹钟、免打扰 | 心跳状态 + soulmate 的闹钟 |
| 最近发生的事 | 时间线：收发消息、记忆写入、做梦、交接、委派、主动发起 | `GET /api/events` 加分类 |

### 3.2 记忆（4 个页签）

| 页签 | 内容 | 操作 |
|---|---|---|
| 短期记忆 | 会话进度、`memo/active/` 列表、交接笔记列表 | 手动交接 |
| 长期记忆 | 第 2 层整体预算条；文件表：token 数、平时和做梦时的权限、前缀状态（"与前缀一致"或"已修改，待生效"） | 打开文件、看 git 历史 |
| 记忆知识库 | 索引状态（片段数、embedding 模型、已索引到的游标、未索引数）；**检索测试**（查询、时间、来源；显示全文、向量、综合三种分数和召回次数） | 重建索引 |
| 做梦记录 | 每次做梦的改动摘要、交回的摘要、对应的 git 提交 | 查看改动、强制入梦 |

检索测试必须和模型调用 `recall` 走**同一套代码**。后台显示的结果就是模型会看到的结果，用来调门槛和切分方式。

### 3.3 状态与主动性

| 区块 | 配置项 / 内容 |
|---|---|
| 心跳 | 白天间隔、深夜间隔、白天和深夜的起始时间（对应 soulmate 的 `tick.*`）；退避规则是固定的，只做说明 |
| 主动消息 | 发到哪里（QQ 私聊对象；以后加桌宠）、免打扰时段、每天主动发起的上限 |
| 当前状态 | 心情、在做什么、想对你说的事的列表 |
| 闹钟 | 时间、备注、是否重复、什么时候定的；可以取消 |
| 主动发起记录 | 时间、触发原因（心跳 / 闹钟 / 委派完成）、内容、你多久之后回复（或没有回复） |

**状态的实现**：
- Persona 提供一个工具 `set_state(mood?, activity?, wants_add?, wants_done?)`，写入工作区的 `state.json`。
- 每次调用后，追加一条内部事件"[状态] …"，**不进前缀**。
- 后台只读 `state.json`，不能修改状态。状态是它自己的。

**主动性闸门**：
- 免打扰时段和每日上限写进环境提示词，提前告诉模型。
- 越界时，发送工具拒绝执行，并在回执里写明原因和恢复时间。
- 判断一条消息是不是"主动发起"：这一批里没有你发来的新消息，却调用了发送工具。

### 3.4 插件与委派

| 区块 | 内容 | 操作 |
|---|---|---|
| 待审批插件 | 名称、用途、由哪个委派任务写成、权限等级、需要的密钥、冒烟测试结果、新增的工具 | 启用 / 查看代码改动 / 拒绝 |
| MCP 服务 | 名称、连接方式（stdio / HTTP）、工具数、权限、状态 | 添加、启用、停用 |
| 委派任务 | 编号、Agent（Codex / Claude Code）、任务、状态、用时、工作目录 | 取消、查看输出 |

- **启停插件会改变工具表，进而重建前缀**。所以启用和停用都在批次边界生效，界面上要写明"损失一次缓存"。
- **启用插件后**，给 bot 推一条事件，比如"插件 weather-mcp 已启用，新增工具 …"，让它知道有了新能力。
- **审批规则可以配置**：只用网络的插件可以设成自动启用；读写文件和执行命令的插件必须手动审批。

### 3.5 备份与迁移（原型里没画）

- git 远程推送状态：最近一次推送时间、远程地址、是否有未推送的提交。
- `data/` 的最近一次备份时间。
- 导出 bundle、导入 bundle（流程见[记忆设计 · 打包迁移](memory.md#7-打包迁移)）。
- profile 列表：每个 profile 的名称、端口、在线状态，可以启动、停止，或从模板新建。

## 4. 访问和安全

- WebUI 只通过 Tailscale 访问，并设置 `web.password`。
- 后台的所有写操作（立即生效、启用插件、取消任务、导入 bundle）都要二次确认。
- 后台从不显示密钥的值，只显示密钥名和"已设置 / 未设置"。

落地时优先使用 Cortico WebUI 的主题变量，上表只用于 Cortico 没有对应变量的地方。
